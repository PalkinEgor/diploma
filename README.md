# Proto-tokens: неавторегрессионная seq2seq-генерация текста

> **Исследовательская работа.** Изучение *прото-токенов* как компактного промежуточного
> представления текста и разработка неавторегрессионной seq2seq-архитектуры, в которой
> **замороженная** языковая модель генерирует ответ за **один прямой проход** — без пошагового
> авторегрессионного декодирования.

📄 **Препринт (AINL 2026): https://arxiv.org/abs/2602.18301**

---

## О прото-токенах

Прото-токены — два обучаемых вектора `e` и `m` размерности `H` (скрытый размер LLM), которые
подаются на вход замороженной модели вместо обычных эмбеддингов токенов. Вектор `e` ставится на
первую позицию входа, вектор `m` повторяется на всех остальных (число повторов равно длине
ответа), после чего замороженная causal-LLM за один проход восстанавливает весь текст. Параметры
модели не изменяются — используются только два вектора. Раскладка входа задаётся в
[`utils.generate_input`](src/proto_tokens/utils.py). На этой схеме построены все эксперименты
работы; она основана на [«Exploring the Latent Capacity of LLMs for One-Step Text
Generation»](https://arxiv.org/abs/2505.21189).

Ниже описаны эксперименты (в порядке от базовой оптимизации к seq2seq-архитектурам), затем —
техническая реализация: установка, запуск, диспетчеризация, формат конфигурации и структура кода.

## Эксперименты

### Оптимизация прото-токенов

Сценарий `proto_fit` ([`training/proto_optimizer.py`](src/proto_tokens/training/proto_optimizer.py)).

Базовая процедура: для каждого текста создаются два вектора `(e, m)` и оптимизируются градиентным
спуском (AdamW) под замороженную LLM. Функция потерь — кросс-энтропия между исходным текстом и
реконструкцией `LLM([e, m, …, m])`. Оптимизация выполняется до `training.maxiter` итераций либо
до достижения порога `training.threshold` по токен-точности; для каждого примера сохраняются
лучшие найденные векторы (движок `NARfit`).

Выход — JSON: на каждый пример `{текст, инструкция, категория, best_vectors: [e, m], accuracy,
last_iter}`. Этот файл используется как обучающая выборка энкодеров seq2seq (с фильтром по
`accuracy`) и как вход для анализа шума и карт внимания.

### Анализ свойств прото-токенов

Эксперименты, изучающие, какая информация закодирована в прото-токенах и как устроено их
пространство. Работают поверх подобранных `(e, m)`.

**Семантика — `paraphrase`** ([`data/generation/paraphrase.py`](src/proto_tokens/data/generation/paraphrase.py)).
Для исходных ответов генерируются два вида аугментаций: лексические искажения через `augmentex`
(CharAug) и смысловые парафразы через генеративную LLM. Результат сохраняется как датасет с полями
`lexical` и `semantic`. Затем для каждого варианта подбираются прото-токены и анализируется
близость представлений исходного текста и его аугментаций.

**Синтаксис — `syntax_cfg` и `syntax_llm`**
([`data/generation/`](src/proto_tokens/data/generation/)). Генерируются предложения семи
грамматических типов (повествовательные, вопросительные, побудительные, односоставные и др.).
`syntax_cfg` строит их по контекстно-свободным грамматикам (nltk, словарь из WordNet и Brown),
`syntax_llm` — генеративной LLM по промптам. Далее для предложений подбираются прото-токены и
проверяется, группируются ли представления по грамматическому типу.

**Карты внимания — `attention`** ([`analysis/attention.py`](src/proto_tokens/analysis/attention.py)).
Один проход декодера с `output_attentions` (внимание в режиме eager); извлекается вклад
прото-токена `e` (внимание к нулевой позиции) в реконструкцию каждого токена, по всем слоям и
головам. Результат — JSON с токенами, векторами и матрицами внимания для последующей визуализации.

**Устойчивость к шуму — `noise`** ([`analysis/noise.py`](src/proto_tokens/analysis/noise.py)).
К вектору `e` добавляется нормированный шум масштаба `α·‖e‖` четырёх типов (gaussian, uniform,
sinusoidal, exponential); измеряется деградация реконструкции (accuracy, длина правильного
префикса) на сетке значений `α`. Показывает чувствительность представления к возмущениям.

### Регуляризация пространства прото-токенов

К оптимизации `proto_fit` можно добавить регуляризатор, согласующий пространство прото-токенов с
пространством внешней модели-эмбеддера (teacher). Teacher-эмбеддинги считаются над теми же
текстами, что реконструируются ([`training/teacher.py`](src/proto_tokens/training/teacher.py)).
Регуляризаторы подключаются списком в конфиге, каждый со своим весом, и добавляются к CE-лоссу на
каждой итерации ([`training/regularizers.py`](src/proto_tokens/training/regularizers.py)).

**Косинусная (якорная), `cosine_anchor`.** Тянет прото-токен `e` к teacher-эмбеддингу его текста:
`L = 1 − cos(e, t·P)`. Размерности прото-токена `H` и эмбеддинга `D` согласуются фиксированной
(по сиду) случайной проекцией `P: D→H` с масштабом Johnson–Lindenstrauss — она сохраняет геометрию
и не обучается.

**Relation distillation, `relation_distillation`.** Сохраняет не абсолютные координаты, а
попарные отношения: матрица `B×B` попарных косинусных близостей прото-токенов в батче подгоняется
(MSE) к такой же матрице teacher-эмбеддингов. Метод размерность-агностичен, но требует батч > 1.

### seq2seq-архитектуры

Обучаемый **энкодер** предсказывает `(e, m)` по входной инструкции, после чего замороженная LLM
декодирует ответ за один проход. Все три архитектуры реализуют единый интерфейс энкодера
([`models/encoders/base.py`](src/proto_tokens/models/encoders/base.py)), обучаются поверх общего
тренерного цикла ([`training/trainers/base.py`](src/proto_tokens/training/trainers/base.py)) и
используют общий замороженный декодер ([`models/decoder.py`](src/proto_tokens/models/decoder.py)).
Различаются только способом получения `(e, m)` и функцией потерь.

**Кодовые книги — `codebook`** ([`models/encoders/codebook.py`](src/proto_tokens/models/encoders/codebook.py)).
Дискретный латент. Вектор размерности `H` делится на `G` групп; в каждой группе — кодовая книга из
`V` обучаемых вариантов. Инструкция кодируется в логиты `(B, G, V)`, из которых Gumbel-Softmax
(`hard=True`) выбирает по одному коду в каждой группе; выбранные коды склеиваются в прото-токен
(всего `Vᴳ` возможных комбинаций). Кодовые книги k-means-инициализируются из подобранных на этапе
оптимизации векторов ([`training/init_codebooks.py`](src/proto_tokens/training/init_codebooks.py)).
Лосс: CE-реконструкция + `diversity_loss_weight · diversity`, где diversity — энтропийный штраф за
равномерное использование кодов (защита от «схлопывания» книг).

**CADA-VAE — `cada_vae`** ([`models/encoders/cada_vae.py`](src/proto_tokens/models/encoders/cada_vae.py)).
Два вариационных автоэнкодера с общим латентным пространством и априором `N(0, I)`: `VAE_T` над
teacher-эмбеддингом инструкции `q`, `VAE_P` над прото-токеном ответа `p = [e; m]` (предсказываются
и `e`, и `m`). Генеративный путь: `q → E_T → z → D_P → (e, m)`. Лосс — четыре слагаемых:
реконструкция внутри доменов (`recon`), KL к априору (`kl`), Cross-Alignment (латент из инструкции
декодируется в прото-токен, и наоборот — `cross_align`), Distribution-Alignment (2-Вассерштейн
между гауссианами энкодеров — `dist_align`), плюс грунтующая CE-реконструкция через замороженный
декодер. Teacher-эмбеддинги инструкций предпосчитываются один раз перед обучением.

**Контрастивная — `contrastive`** ([`models/encoders/contrastive.py`](src/proto_tokens/models/encoders/contrastive.py)).
Прямое предсказание непрерывных `(e, m)` проекционными головами энкодера + головы предсказания
длины ответа (`mu`, `std`). Лосс объединяет: CE-реконструкцию текста через замороженный декодер;
восстановление самих прото-токенов контрастивными функциями против целевых векторов этапа
оптимизации — InfoNCE (позитив — совпадающий индекс в батче) и DBLL (distance-based logistic
loss); ошибку предсказания длины (gaussian NLL). Веса слагаемых — в `training.loss_weights`.

## Техническая реализация

### Установка

Требуется Python ≥ 3.9 и GPU (замороженные LLM грузятся в `bfloat16`).

```bash
pip install -e .            # или: pip install -r requirements.txt
```

Зависимости: `torch`, `transformers`, `datasets`, `sentence-transformers`, `scikit-learn`,
`peft`, `nltk`, `augmentex`, `python-dotenv`, `tqdm`, `pyyaml`, `huggingface_hub`.

### Запуск и диспетчеризация

Все эксперименты запускаются одной командой через единую точку входа; конкретный сценарий задаётся
полем `experiment.type` в YAML-конфиге:

```bash
python scripts/run.py --config <путь-к-конфигу>.yaml
```

Внутри работает диспетчер: каждый сценарий — это класс, реализующий контракт
[`Runnable`](src/proto_tokens/base.py) (`from_config(config)` + `run()`) и зарегистрированный под
строковым ключом в реестре ([`registry.py`](src/proto_tokens/registry.py)). Точка входа
([`experiment.py`](src/proto_tokens/experiment.py)) по значению `experiment.type` находит нужный
класс, собирает его из конфига и запускает. Регистрация выполняется при импорте (через файлы
`__init__.py`), поэтому добавление нового сценария не требует правки диспетчера.

| `experiment.type` | Что делает | Конфиг |
|---|---|---|
| `proto_fit` | оптимизация прото-токенов (+ опц. регуляризация) | `configs/stage1_protofit/` |
| `paraphrase` | аугментации (лексические + семантические) | `configs/analysis/paraphrase.yaml` |
| `syntax_cfg` | генерация синтаксиса по грамматикам | `configs/analysis/syntax_cfg.yaml` |
| `syntax_llm` | генерация синтаксиса через LLM | `configs/analysis/syntax_llm.yaml` |
| `attention` | карты внимания декодера | `configs/analysis/dolly_llama_attention.yaml` |
| `noise` | устойчивость к шуму | `configs/analysis/dolly_llama_noise.yaml` |
| `teacher_embeddings` | предпосчёт teacher-эмбеддингов | `configs/analysis/dolly_teacher_embeddings.yaml` |
| `codebook` | обучение энкодера на кодовых книгах | `configs/stage2_seq2seq/dolly_llama_codebook.yaml` |
| `cada_vae` | обучение энкодера CADA-VAE | `configs/stage2_seq2seq/dolly_llama_cada_vae.yaml` |
| `contrastive` | обучение контрастивного энкодера | `configs/stage2_seq2seq/dolly_llama_contrastive.yaml` |

Порядок использования: `proto_fit` даёт JSON с подобранными `(e, m)`; на этом JSON затем работают
и анализ, и обучение энкодеров seq2seq (у второго конфига `dataset.path` = выход `proto_fit`).

### Формат конфигурации

Единая схема для всех сценариев. Обязательно только поле `experiment.type`; остальные разделы
интерпретирует конкретный сценарий:

| Раздел | Назначение |
|---|---|
| `model` | путь и dtype LLM; для seq2seq — под-раздел `encoder` с параметрами архитектуры |
| `dataset` | путь и тип данных (`dolly` / `alpaca` / `noise`) |
| `training` | гиперпараметры сценария (batch_size, эпохи/итерации, seed, веса лоссов и т. д.) |
| `regularizers` | (опц.) список регуляризаторов пространства, каждый со своим весом |
| `teacher` | (опц.) внешний эмбеддер для регуляризации или CADA-VAE |
| `logging` | пути сохранения результатов, логов, весов |

Пути в конфигах — кластерные (`/userspace/pes/...`); перед запуском в другом окружении их нужно
поправить. Пример этапа оптимизации с регуляризацией:

```yaml
experiment:
  type: proto_fit
model:   { path: <llama>, dtype: bfloat16 }
dataset: { path: <dolly>, type: dolly, max_samples: 2000 }
training: { batch_size: 8, maxiter: 2000, threshold: 0.98, max_tokens: 256, seed: 42 }
teacher: { path: <qwen3-embedder>, dtype: bfloat16, normalize: true }
regularizers:
  - { name: cosine_anchor, weight: 0.1, seed: 42 }
  - { name: relation_distillation, weight: 0.1 }
logging: { save_path: <результат>.json, save_log_path: <лог>.log, save_every: 10 }
```

### Структура репозитория

```
src/proto_tokens/            # исходный код (устанавливаемый пакет)
├── base.py                  # Runnable — контракт эксперимента (from_config + run)
├── registry.py              # реестры + диспетчеризация по experiment.type
├── experiment.py            # run_experiment(config) — точка сборки/запуска
├── utils.py                 # generate_input (схема входа), сиды, load_config
├── metrics.py               # токен-уровневые метрики
├── runtime.py               # загрузка модели/токенизатора/даталоадера/оптимизатора
├── data/
│   ├── datasets.py          # фабрика датасетов (alpaca|dolly|noise × nar|end2end)
│   ├── collators.py         # фабрика коллаторов
│   └── generation/          # syntax_cfg · syntax_llm · paraphrase
├── models/
│   ├── decoder.py           # FrozenDecoder — замороженная LLM (общая)
│   └── encoders/            # base (интерфейс) + codebook · cada_vae · contrastive
├── training/
│   ├── proto_optimizer.py   # оптимизация прото-токенов (NARfit)
│   ├── regularizers.py      # cosine_anchor · relation_distillation
│   ├── teacher.py           # teacher-эмбеддер
│   ├── init_codebooks.py    # KMeans-инициализация кодовых книг
│   └── trainers/            # общий BaseTrainer + по тренеру на архитектуру
└── analysis/                # noise · attention
scripts/run.py               # единая точка входа
configs/                     # конфиги: stage1_protofit / stage2_seq2seq / analysis
notebooks/                   # downstream-анализ результатов (кластеризация, графики)
```

### Расширение

Реестры позволяют добавлять компоненты без правки диспетчера: новая архитектура — класс энкодера
(`ProtoEncoder`) + тонкий тренер (`BaseTrainer`) с декоратором регистрации; новый регуляризатор —
класс с декоратором, включаемый списком в конфиге; новый датасет — ветка в фабриках датасета и
коллатора.
